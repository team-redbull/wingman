# Upgrade: 3.61 → 3.62 (secrets from an existing Secret; deploying through redbull-platform)

For an agent (or a person) on a cluster that runs Wingman. Follow the steps in
order. **STOP** means: change nothing more, finish the report (step 8) and
hand it back.

`<ns>`, `<release>`, `<tag>` and `$CHART` mean what they mean in
[3.3-to-3.4.md](3.3-to-3.4.md); `<tag>` is `3.62.0` or a later 3.62 release.
`<secret>` is the name you give the existing Secret (`wingman-credentials`
below), and `<client>` is `auth.oauthClientId` (default `wingman-app`).

## 1. What changes

Wingman moved to `team-redbull/wingman`; its images are
`ghcr.io/team-redbull/wingman-{day1,day2,web}` from 3.61.0 on, and each release
also writes its chart into redbull-platform, whose Argo CD deploys it where its
ApplicationSet runs (ADR-0070). The chart gains two switches, both off by
default:

| Value | Default (3.61's behaviour, unchanged) | Set |
|---|---|---|
| `secrets.existingSecret` | `""`: the chart renders `wingman-secrets` from `gitlab.accessToken`, `gitlab.webhookSecret`, `auth.oauthClientSecret`, `auth.jwtSecret`, `devAuth.secret` | A Secret's name: the chart renders no Secret, and day1 and day2 read that one (keys `GITLAB_TOKEN`, `JWT_SECRET_KEY`, `OPENSHIFT_OAUTH_CLIENT_SECRET`, optionally `GITLAB_WEBHOOK_SECRET`, `DEV_AUTH_SECRET`). The render fails while any of the five values is set |
| `auth.oauthClient.create` | `true`: the chart renders the OAuthClient with its secret inline | `false`: none; it is made by hand. Required with `secrets.existingSecret` on OpenShift without dev login |

**Nothing to do to stay as you are.** A Helm deployment that keeps its secrets
in its values takes 3.62 as the [generic upgrade](README.md#the-generic-upgrade-no-guide):
the render is byte-identical to 3.61's. **The air-gap stays this way**: it
installs by Helm from a mirrored release, as before.

This guide is for adopting the new mode: **A**, a Helm deployment that wants no
secret in its values; **B**, a cluster whose Wingman moves from its Helm release
to redbull-platform's Argo CD (the lab cluster). No new grant, network rule or
metric.

## 2. What to bring in

The three images of `<tag>` and the repository at `v<tag>`, as for any release
(for B, redbull-platform's CI copy is the chart; no image comes by hand).

## 3. Discover and check (read-only)

1. **The release and its secret values** (prints only whether each is set):

   ```bash
   helm list -n <ns>
   helm get values <release> -n <ns> -o json | python3 -c "
   import json, sys
   v = json.load(sys.stdin)
   for path in ('gitlab.accessToken', 'gitlab.webhookSecret', 'auth.oauthClientSecret', 'auth.jwtSecret', 'devAuth.secret'):
       node = v
       for key in path.split('.'):
           node = (node or {}).get(key) if isinstance(node, dict) else None
       print(path, 'set' if node else 'empty')"
   ```

   No release, or not deployed: **STOP**.
2. **The chart's Secret holds the keys** (names only):

   ```bash
   kubectl -n <ns> get secret wingman-secrets -o json | python3 -c \
     "import json, sys; print(sorted(json.load(sys.stdin)['data']))"
   ```

   It must list `GITLAB_TOKEN`, `JWT_SECRET_KEY` and `OPENSHIFT_OAUTH_CLIENT_SECRET`.
   Missing: **STOP**.
3. **The OAuthClient exists** (OpenShift without dev login):
   `oc get oauthclient <client> -o jsonpath='{.redirectURIs}'; echo` prints
   `["https://<route host>/login"]`. Missing: **STOP**.
4. **For B only**: redbull-platform's `gitops/services/wingman/app.yaml` and
   `gitops/overrides/wingman.yaml` exist on its `main`, or in the pull request
   that adds them, and the override sets `secrets.existingSecret: <secret>` and
   `auth.oauthClient.create: false`, and no secret. Not so: **STOP**.

## 4. Make the Secret and keep the OAuthClient (A and B)

1. Copy the chart's Secret to `<secret>`, without printing a value:

   ```bash
   kubectl -n <ns> get secret wingman-secrets -o json | python3 -c "
   import json, sys
   s = json.load(sys.stdin)
   print(json.dumps({'apiVersion': 'v1', 'kind': 'Secret', 'type': 'Opaque',
     'metadata': {'name': '<secret>', 'namespace': s['metadata']['namespace']}, 'data': s['data']}))" \
     | kubectl apply -f -
   ```

   Empty keys copy as empty, which is what the chart's Secret gave the pods.
2. Keep the OAuthClient when the chart stops rendering it (Helm would delete it
   on the upgrade, and nobody could log in):

   ```bash
   oc annotate oauthclient <client> helm.sh/resource-policy=keep
   ```

Its secret stays the one in `OPENSHIFT_OAUTH_CLIENT_SECRET`: nothing else changes.

## 5A. Upgrade, keeping Helm

```bash
helm history <release> -n <ns> | tail -3          # note the current revision, for a rollback
helm upgrade <release> $CHART -n <ns> --reset-then-reuse-values \
  --set image.day1.tag=<tag> --set image.day2.tag=<tag> --set image.web.tag=<tag> \
  --set secrets.existingSecret=<secret> --set auth.oauthClient.create=false \
  --set gitlab.accessToken=null --set gitlab.webhookSecret=null --set auth.oauthClientSecret=null \
  --set auth.jwtSecret=null --set devAuth.secret=null
kubectl -n <ns> rollout status deploy -l app.kubernetes.io/part-of=wingman --timeout=5m
```

Helm deletes `wingman-secrets` (no longer rendered) and keeps the OAuthClient
(step 4.2). A render that fails naming one of the five values: a value file
passed with `-f` still sets it; drop it there.

## 5B. Move to redbull-platform's Argo CD

1. **The namespace.** The `namespaces` Helmfile release owns every service's
   namespace (CreateNamespace is off). Add `<ns>` to
   `charts/namespaces/values.yaml` (`namespaces` and `argocd.managedNamespaces`)
   in the same pull request as the service. A namespace that exists already
   (made by `helm install --create-namespace`) is adopted before that release
   runs, or Helm refuses it:

   ```bash
   oc label ns <ns> app.kubernetes.io/managed-by=Helm --overwrite
   oc annotate ns <ns> meta.helm.sh/release-name=namespaces meta.helm.sh/release-namespace=default --overwrite
   helmfile -l name=namespaces sync          # from the redbull-platform checkout
   ```

2. **Merge the redbull-platform pull request.** The ApplicationSet makes the
   Application `wingman` and syncs it: it applies the same Deployments,
   Services, ConfigMaps and Route the Helm release made, now reading `<secret>`.
   Watch it until it is Synced and Healthy:

   ```bash
   oc -n openshift-gitops get application wingman -o jsonpath='{.status.sync.status} {.status.health.status}'; echo
   ```

3. **Retire the Helm release's record, never its objects.** Argo owns them now;
   `helm uninstall` would delete what Argo runs. Delete only Helm's record, and
   the chart's old Secret, which nothing reads:

   ```bash
   kubectl -n <ns> delete secret -l owner=helm,name=<release>
   kubectl -n <ns> delete secret wingman-secrets
   ```

From now on nobody runs `helm upgrade` there: every Wingman release pushes its
chart and Argo syncs it. A cluster's values change in
`gitops/overrides/wingman.yaml`, by a pull request to redbull-platform.

## 6. Verify

1. `kubectl -n <ns> get deploy wingman-day1 wingman-day2 -o jsonpath='{range .items[*]}{.spec.template.spec.containers[0].envFrom[1].secretRef.name}{"\n"}{end}'`
   prints `<secret>` twice.
2. `kubectl -n <ns> get secret wingman-secrets` answers NotFound; the pods are
   ready with no restarts, and `kubectl -n <ns> logs deploy/wingman-day1 | grep -c Traceback`
   prints `0`.
3. Sign in to Wingman with OpenShift and open the cluster list.

## 7. Roll back

- **A**: `helm rollback <release> <revision> -n <ns>` renders `wingman-secrets`
  again from the old values and takes the OAuthClient back; then delete
  `<secret>`.
- **B**: revert the Wingman commit in redbull-platform that brought the problem
  (Argo syncs the chart before it). **Never delete `gitops/services/wingman/`
  to go back**: the ApplicationSet's finalizer then deletes every Wingman
  workload. Going back to Helm is a planned move, not a rollback step:
  **STOP** and report.

## 8. Report

What step 3 found (no values), which path you took, each command and its
result, and step 6's output. Name Secrets and keys, never their values.
