# Upgrade: 3.70 → 3.71 (each zone's NodePool labels its Nodes with its zone)

For an agent inside the disconnected environment. Follow the steps in order.
**STOP** means: change nothing more, finish the report (step 7) and hand it
back.

`<ns>`, `<release>`, `<tag>` and `$CHART` mean what they mean in
[3.3-to-3.4.md](3.3-to-3.4.md); `<tag>` is `3.71.0` or a later 3.71 release.

## 1. What changes

The naming convention has every NodePool label its Nodes with its zone, and
the upgrade workflow reads that label to upgrade a cluster zone by zone
(ADR-0072's 2026-11-28 amendment).

| Area | 3.70 | 3.71 |
|---|---|---|
| A create | Each zone's NodePool with the nodepool's node labels only | Each NodePool of a convention InfraEnv (`<flavor>-<mtl\|kv<cpu>>-az<n>`) also gets `nodeLabels: {topology.kubernetes.io/zone: <its zone>}` |
| Refused (422) | — | A create whose node labels give `topology.kubernetes.io/zone` another value than each NodePool's zone; a flavor that sets the key; a create whose rendered file does not hold the label (the template, step 3.1) |
| Drift and Sync | — | The zone label is never a flavor's drift; a NodePool without it is listed under the drift read's `zone_labels`, and the next sync adds it |
| Node types | Any `<word>-<mtl\|kv<n>>-<word>` | The convention's grammar exactly: a flavor from a letter (with its variant letter: `c200n` is its own node type), `kv` with a positive count, a zone `az<n>`. Any other name is a node type of its own, in one zone |
| Chart, Secrets, grants, settings, metrics | — | Nothing new |

## 2. What to bring in from the connected side

The three images of `<tag>` and the repository at `v<tag>`, as for any
release. The reference template is
`dev/gitlab-fixtures/wingman/cluster-specs/cluster-template.j2` in that
repository.

## 3. Discover (read-only)

1. **The specs template's node labels.** In the specs project
   (`gitlab.specsProjectId`), open `cluster-template.j2` on the default branch
   and find, inside the nodepool loop:

   ```jinja
   {% if np.node_labels | default({}) %}
       nodeLabels: {{ np.node_labels | default({}) | tojson }}
   {% endif %}
   ```

   - Found: nothing to change.
   - Not found, or behind another condition: 3.71 refuses every create of a
     convention InfraEnv (422, `nodepool[0].nodeLabels: the template wrote no
     topology.kubernetes.io/zone …`, naming this guide). Open a merge request
     in the specs project that adds those lines below `labels:`, as the
     reference has, and have it reviewed and merged before step 4.
   - In another shape (`nodeLabels` written from something else): **STOP** and
     report the lines.
2. **The chart renders them.** In the hostedclusters-setup chart the MCEs'
   ApplicationSets use, open `templates/nodepool.yaml` and look for
   `nodeLabels`. A NodePool's `spec.nodeLabels` from the entry's `nodeLabels`:
   the label reaches the Nodes. Missing: the label stays in the cluster file
   and reaches no Node; nothing breaks in Wingman, but record it for the
   team (the convention's open item 3).
3. **Flavors that set the key.** In the specs project, search `specs/*.yaml`
   for `topology.kubernetes.io/zone`. Each such flavor loads with a warning,
   its next save is refused, and a create from it that spreads over zones is
   refused: record them for their owners.
4. **InfraEnvs off the exact grammar.** On each Customer MCE,
   `oc get infraenvs -A -o name` and record the names that are not
   `<flavor>-<mtl|kv<cpu>>-az<n>` with a flavor that starts with a letter:
   their customers see each as a node type of its own, in one zone, and
   Wingman writes no zone label for it.

## 4. Upgrade

The [generic upgrade](README.md#the-generic-upgrade-no-guide) to `<tag>`:
the chart at `v<tag>` and the three images, with the values you already
have.

## 5. Verify

1. On **New Cluster**, pick a node type with several zones and **Review** (it
   commits nothing): each zone's `nodepool[]` entry has
   `nodeLabels` with `topology.kubernetes.io/zone` set to its own zone.
2. A cluster created by 3.70 from a flavor: its drift is what it was, and its
   **Sync** preview lists `adds topology.kubernetes.io/zone: <zone> to
   nodepool …` among its warnings.

## 6. Roll back

The images back to 3.70, the generic way. The labels 3.71 wrote stay in the
files; 3.70 keeps them as node labels, and its drift compares a locked
`node_labels` with them included.

## 7. Report

What step 3 found (the template's lines and any merge request, the chart's
`nodeLabels`, the flavors that set the key, the InfraEnvs off the grammar),
the upgrade's result, and step 5's checks.
